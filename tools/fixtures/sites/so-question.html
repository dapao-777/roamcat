Why is conditional processing of a sorted array faster than of an unsorted array?

In this C++ code, sorting the data before the timed region makes the primary loop roughly six times faster than leaving the array unsorted, and the cause turns out to be branch prediction rather than anything the sort itself does.

At first I assumed this must be a language or compiler anomaly, so I tried equivalent code in another language and it produced a similar but less extreme result.

for (unsigned i = 0; i < 100000; ++i) { if (data[c] >= 128) sum += data[c]; }

The reason why performance improves drastically when the data is sorted is that the branch predictor can learn a simple repeating pattern instead of guessing a coin flip on every iteration of the loop.

In a typical x86 processor the execution of an instruction is divided into several stages in a pipeline, and a wrongly predicted conditional jump discards all of the speculative work downstream.
